# Kurenai Studio 技术文档

本文描述当前 **CLI → cocos host → cocos-cli** 架构下的运行方式与开发约定。历史迁移背景与清单见 [cocos-cli-migration.md](cocos-cli-migration.md)。

## 1. 设计目标（简述）

Kurenai 让 Agent 直接维护磁盘上的 Cocos 工程源码，引擎只负责导入、编译、预览与构建。人提出意图，Agent 改文件并调用 `kurenai` 命令获取 uuid、日志和预览反馈；不在 Creator 编辑器里点选操作。

```text
Agent（写 assets/** + 调 kurenai …）
  → kurenai CLI（短进程，按需拉起 host）
  → cocos host（每工程一个常驻进程，加载 cocos-cli）
  → 浏览器游戏预览 + asset-db 导入 / 脚本编译
```

库侧（`lib/`）提供 `ProjectControl`（模板、上下文、publish）、`PreviewController`（启动或附着 host）和 `PreviewBridge`（预览反代与 inspector 注入），供 Studio 页面与测试使用。

## 2. 进程模型

| 组件 | 入口 | 生命周期 |
|------|------|----------|
| **kurenai CLI** | `bin/kurenai.mjs` | 每次命令一个 Node 进程，stdout 输出 JSON（`context` 除外） |
| **cocos host** | `bin/kurenai-cocos-host.mjs` | **每个 Cocos 工程最多一个**；加载 cocos-cli 的 runtime、asset-db、packer 与游戏预览服务 |

Host 就绪后会在 `<project>/temp/kurenai-host.json` 写入：

```json
{
  "pid": 12345,
  "serverUrl": "http://127.0.0.1:7460/",
  "previewUrl": "http://127.0.0.1:7460/?scene=..."
}
```

CLI 与 `PreviewController` 都通过该文件发现 host。进程退出时 host 会删除此文件。运行日志在 `<project>/temp/kurenai-host.log`。

**为何一工程一 host：** cocos-cli 的 `Launcher` 依赖进程内全局单例，同一 Node 进程无法同时服务两个工程目录。

**CLI 常用命令：**

- `kurenai host start|status|stop [--project <dir>]` — 显式管理 host
- `kurenai asset info <file>` — 需要 host 时会在后台 `ensureHost`（最长约 180s 等待 `ready`）
- `kurenai logs [--since <seq>] [--errors]`
- `kurenai context` — 人类可读的工程与预览摘要
- `kurenai init <dir> --template base-ai|base-ai-3d`
- `kurenai publish [--platform web-desktop|web-mobile] …`

工程目录默认规则：从 cwd 或文件路径向上查找同时存在 `assets/` 与 `package.json` 的目录。

## 3. Host HTTP 接口

与游戏预览 **同源**（`serverUrl`），由 host 注册在 cocos-cli 中间件上：

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/__kurenai/status` | 返回 host 状态；`ready` 表示预览 settings 可用 |
| GET | `/__hmr/status` | 兼容旧契约：`ready` 时 200，否则 503 |
| POST | `/__kurenai/refresh?path=<相对或绝对路径>` | 对 `assets/` 内路径调用 `assetManager.refreshAsset` |
| GET | `/__kurenai/asset?path=…` | 先 refresh，再返回 asset-db 的 uuid、type、subAssets 等 |
| GET | `/__kurenai/logs?since=<seq>&errors=1` | 环形缓冲的 host / 编译 / 转发浏览器日志 |

路径必须在 `<project>/assets/` 下，否则 400。

**环境变量（host）：**

- `PROJECT`（必填）、`PORT`（默认 7460，可能被 cocos-cli 换端口）
- `LAUNCH_SCENE` — 启动场景 db:// 或 uuid；默认读 `settings/v2/packages/project.json` 的 `startScene`
- `KURENAI_COCOS_CLI_ROOT` — cocos-cli 安装目录
- `WATCH=0` — 关闭文件监听
- `WATCH_POLL=1`、`WATCH_POLL_MS`（默认 1000）— 见下一节

## 4. 文件变更：watch 与 WATCH_POLL

cocos-cli **没有**内置 `assets/` 文件系统监听。Host 在预览就绪后自行监听磁盘变化，去抖后调用 `refreshAsset`，再走 asset-db 导入、脚本 `compiled` 事件与 cocos-cli live-reload（浏览器刷新）。

- **默认：** 对 `assets/` 使用 `fs.watch`（递归）。
- **Docker bind mount 等场景：** 设置 `WATCH_POLL=1`，按间隔扫描 mtime+size；逻辑与 watch 共用同一去抖队列。详见 [docker-watch-poll.md](docker-watch-poll.md)。

`.meta` 由 asset-db 在导入时重写；host 在 refresh 结束后有一段 quiet 窗口，避免把引擎写 meta 误判为外部编辑而循环刷新。

## 5. PreviewBridge 与 attach

**PreviewBridge**（`src/preview/bridge.ts`）在本机另开 HTTP 端口（默认 `PORT+1`），反代 cocos 预览 upstream，并：

- 把 HTML 里写死的 `window.WebEnv.serverURL` 改成 `location.origin`，避免 import map / 场景 JSON 绕过 bridge 直连 host 端口；
- 在 `/` 页面注入 `/__kurenai/inspector.js`，支持预览内选中节点等能力。

**PreviewController.start()** 两种路径：

1. **附着（attach）：** 若 `temp/kurenai-host.json` 存在、pid 存活且 `/__kurenai/status` 的 `ready === true`，则 **不再 spawn host**，`attached: true`，只启动 PreviewBridge。`stop()` **仅关闭 bridge**，不结束已由 CLI 或其他方启动的 host。
2. **自启：** 否则 spawn `kurenai-cocos-host.mjs`，轮询 `/__kurenai/status` 直到 ready，再启动 bridge。`stop()` 会终止自启的 host 子进程。

cocos-cli 若因端口占用换端口，controller 会从 host 日志或 status 中的 `url` 修正 upstream。

## 6. 工程编写模型（Agent）

完整规则见模板内 `templates/shared/AGENTS.md`。要点：

- **无 Creator 编辑器：** 直接写 prefab（`.prefab`）、材质（`.mtl`）、脚本与资源文件；行为写在 TypeScript **View** 里（`MainView.bind(root)` 等），prefab **不含脚本组件**。
- **目录约定：** 代码在 `assets/game/`；prefab / 材质 / 其他资源在 `assets/resources/` 下对应子目录；不要改 `assets/kurenai/Boot.ts` 与 `*.scene`。
- **`.meta` 由引擎生成：** Agent **不要**手写或编辑 `.meta`。先写入源文件，再执行：

  ```sh
  kurenai asset info assets/resources/materials/red.mtl
  ```

  成功时 JSON 含 `asset.uuid` 与 `subAssets`；prefab / 材质 JSON 里用 `__uuid__` 引用。失败时根据 `error` 修正文件后重试。
- **反馈闭环：** 保存源文件 → host watcher 或 CLI 触发的 refresh → 编译 → 预览自动 reload。改磁盘，不要改运行中页面的内存状态。
