# Kurenai Studio 简单使用方法

Kurenai 面向 **Agent 与开发者**：用 `kurenai` CLI 初始化 Cocos 工程、启动预览 Host，直接编辑磁盘上的源码与资源；Host 监听 `assets/` 变更并刷新预览。  
安装与环境见 [安装方法.md](安装方法.md)；架构背景见 [cocos-cli-migration.md](cocos-cli-migration.md)。

## 一句话上手（给 Agent）

与 [安装方法.md](安装方法.md) / 仓库 [README](../README.md) 首页同一句：

```text
自学并只用最新 kurenai CLI（https://github.com/kurenai-studio/kurenai：clone 后 Node.js 22+ 下 `npm install && npm link`，确认本机有 PinK 的 cocos-cli 或设 `KURENAI_COCOS_CLI_ROOT` → `kurenai init` → `host start` → 按项目 `AGENTS.md` 只改 `assets/game/` 与 `assets/resources/`，用 `asset info` / `logs` / `context` 闭环，禁止手写 .meta、prefab 不挂脚本）开发 Cocos 游戏；交付时再 `kurenai publish --platform web-desktop`。
```

## 一、创建新工程并启动预览

在空目录外执行 `init`（会在目标目录写入模板），进入工程后启动 Host：

```powershell
kurenai init D:\path\to\my-game --template base-ai
Set-Location D:\path\to\my-game
kurenai host start
```

- **2D** 模板：`base-ai`
- **3D** 模板：`base-ai-3d`

`host start` 在后台启动 cocos-cli 预览 Host，输出 JSON，其中包含预览 URL。Host 状态写入 `temp/kurenai-host.json`；同一工程只需一个 Host。

macOS / Linux 示例：

```bash
kurenai init ~/my-game --template base-ai-3d
cd ~/my-game
kurenai host start
```

在其他目录对同一工程操作时，加上 `--project`：

```powershell
kurenai host status --project D:\path\to\my-game
kurenai host stop --project D:\path\to\my-game
```

## 二、推荐工作循环

1. 修改工程内的源文件（见下一节路径约定）。
2. Host 检测到 `assets/` 变化后自动导入、编译并刷新浏览器预览。
3. 用 `kurenai logs` 查看编译错误或浏览器控制台；必要时用 `kurenai asset info` 确认资源 uuid。
4. 在浏览器中查看预览效果，继续迭代。

查看日志（仅错误）：

```powershell
kurenai logs --errors
```

从指定序号之后增量拉取：

```powershell
kurenai logs --since 42
```

## 三、写哪里、怎么写（简要）

工程初始化后会复制 [`templates/shared/AGENTS.md`](../templates/shared/AGENTS.md) 到项目根目录的 `AGENTS.md`。**完整编写规则以该文件为准**；此处只概括常见模式：

| 内容 | 路径 |
|------|------|
| 游戏逻辑（TypeScript） | `assets/game/`，入口为 `MainView.ts` 的 `bind(root)` |
| Prefab（结构、外观，不含脚本） | `assets/resources/prefabs/` |
| 材质 | `assets/resources/materials/` |
| 其它资源 | `assets/resources/` |

- **Prefab**：描述节点树与渲染组件，不在 Prefab 里挂自定义脚本；多个 Prefab 在代码里组合。
- **Material**：编写 `.mtl` 等源文件，引用引擎内置 effect 的 uuid（见 `AGENTS.md` 中的表格）。
- **View**：在 `MainView.bind` 或独立 View 里 `loadPrefab(...)`，实例化后 `addComponent(...).bind(node)` 绑定行为。

不要手改 `.meta`；写入或修改资源文件后，用 CLI 让引擎导入并查询 uuid：

```powershell
kurenai asset info assets/resources/materials/red.mtl
```

成功时返回 `uuid` 与 `subAssets`；`ok: false` 表示导入失败，需修正源文件后重试。

## 四、查看工程上下文

```powershell
kurenai context
```

输出当前工程状态及 `AGENTS.md` 摘要，便于 Agent 对齐项目约定。

## 五、发布构建

```powershell
kurenai publish --platform web-desktop --out .\dist
```

可选平台还包括 `web-mobile`；需要更详细构建日志时加 `--verbose`。

## 六、预览没有更新或报错

1. 确认文件已保存到磁盘上的 `assets/`。
2. 运行 `kurenai logs --errors` 查看编译与运行时错误。
3. 若 Host 异常，先 `kurenai host stop`，再 `kurenai host start`。
4. Docker 等环境下文件监听不可靠时，可启用轮询（见 [docker-watch-poll.md](docker-watch-poll.md)）。

## 七、结束工作

- 暂时停止预览：`kurenai host stop`（仅关闭当前工程的 Host 进程）。
- 下次继续：在同一工程目录执行 `kurenai host start`，或从任意路径加 `--project` 启动。
