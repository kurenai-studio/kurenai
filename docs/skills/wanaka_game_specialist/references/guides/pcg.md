# Procedural worlds

Use PCG when the game needs a streamed Nature, City, Cave, OffWorld, or Underwater
world. Read only the declarations for the imports used by the project:

- `pcg-author.d.ts` defines worlds, bases, regions, sites, layers, and plans.
- `pcg-three.d.ts` attaches a world to the Engine scene.
- `pcg-kit-*.d.ts` exposes the reviewed presets and semantic roles for one kit.

Start from [pcg-world.ts](../../examples/pcg-world.ts). It is the canonical
complete integration slice.

## Define the world

Use one `definePcgWorld` declaration shared by Edit and Play. For a city or
endless urban world, start with a flat Base and constant development so the
terrain supports connected streets and developed blocks:

```ts
import { bases, definePcgWorld } from 'wanaka-studio-engine/pcg-author';
import 'wanaka-studio-engine/pcg-kit-city';

export const world = definePcgWorld({
  base: bases.flat({
    environment: 'temperate',
    streaming: 'far',
    urbanization: { mode: 'constant', class: 'commercial', intensity: 0.9 },
  }),
  seed: 'endless-city',
});
```

Intensity controls development tier, building occupancy and height; it is not
an urban land-coverage percentage. Constant development does not flatten terrain
or remove water. Roads and building lots still obey terrain and water constraints.

Choose a Nature Base when the request calls for natural surroundings, hills or
a coast. For a bounded city within that landscape, add a City Region:

```ts
import { regions } from 'wanaka-studio-engine/pcg-author';
import { presets as nature } from 'wanaka-studio-engine/pcg-kit-nature';
import { presets as city } from 'wanaka-studio-engine/pcg-kit-city';

export const landscapeWorld = definePcgWorld({
  base: bases.preset(nature.temperateNature),
  seed: 'coastal-city',
  regions: [
    regions.city({
      id: 'city',
      preset: city.natureCity,
      position: { x: 0, z: 0 },
    }),
  ],
});
```

For endless development over that natural landscape, put constant urbanization
on its Base instead of adding a bounded Region. The natural relief and coast
remain; reducing Nature density changes vegetation, not the terrain or city coverage.

Use `mode: 'procedural'` for settlements that follow terrain, with optional `bias`,
`frequency`, and `maxIntensity`. Import both City and Village kits for mixed
procedural development. Constant intensity from 0.55 builds City towers, shorter toward 0.55 and a full skyline from 0.8; below 0.55 it uses Village assets. City and
Village Regions are local overrides; later declarations win where they overlap.
Industrial development stays low, and park development leaves land unbuilt.

Import the kits used by the selected development tiers.

## Attach the world

Attach the declaration once through `attachPcgWorld`. The host owns streaming,
generation, presentation, resource lifetime, and teardown.

Use `attachPcgWorld(..., { onProgress })` for attachment phases and available initial cell counts; totals may change, and `attached` does not mean gameplay-ready.

```ts
import { attachPcgWorld } from 'wanaka-studio-engine/pcg-three';

const attachment = await attachPcgWorld(context, world, {
  parent,
  interest: () => player.position,
  physics,
});
context.scope.own(attachment);
```

Pass `physics` only in Play. Edit may attach the same declaration without it.
Do not create another worker, streamer, water registry, asset session, or
presentation host in project code.

For a Terrain Base, keep the palette's semantic slots and bind project textures
through `terrainSurfaces` when the default look does not fit the scene:

```ts
import * as THREE from 'three/webgpu';

const snow = context.scope.own(await new THREE.TextureLoader().loadAsync(snowTextureUrl));
snow.colorSpace = THREE.SRGBColorSpace;
snow.wrapS = snow.wrapT = THREE.RepeatWrapping;
const attachment = await attachPcgWorld(context, world, {
  parent,
  interest: () => player.position,
  physics,
  terrainSurfaces: {
    'surface-snow': { map: snow, metersPerRepeat: 8, roughness: 0.96 },
  },
});
context.scope.own(attachment);
```

Use this with a Base declaring `surface-snow` in its palette. Omitted slots keep
their default maps. An override can also supply `normal`, `roughnessMap`,
`metalnessMap` and `tint`; normal and scalar maps use data colour space. The
project owns these Three textures. The same bindings shade streamed terrain and
its underwater refraction receiver, while the height Field, surface weights and
collision remain generated by PCG. Share the texture-loading and attachment
function between Edit and Play; keep renderer textures out of worker callbacks.

## Add generated structure

Use a Plan for a structure generated once per macro region and consumed by many
streamed cells, such as a road, track, or river. Use a Layer only for a cell-local
rule. Keep Plan and Layer callbacks pure and deterministic.

```ts
import { definePcgPlan, splines } from 'wanaka-studio-engine/pcg-author';

const roads = definePcgPlan({
  id: 'game.roads',
  version: 1,
  outputs: {
    roads: { kind: 'splines', present: { as: 'path', width: 4 } },
  },
  params: {},
  plan: ({ region }) => ({
    roads: splines.network(
      splines.create(`${region.id}/road`, [
        { x: region.bounds.minX, z: 0, height: 0 },
        { x: region.bounds.maxX, z: 0, height: 0 },
      ]),
    ),
  }),
});
```

To reserve planting space independently of rendering, a Plan polygon or spline output can
set `scatterExclusion: true` or `{ margin: 3 }`; spline options can also provide a fallback
full `width`. Use `scatterExclusion: false` to opt out of a road/path/paving reservation.
A point Layer output can set `avoidPlanOccupancy: true` for any role, with an optional
`planOccupancyRadius` in metres before instance scale. Use `false` for a deliberate object
on the route. With no explicit radius, kit model bounds provide the envelope when available;
default props without kit bounds use their placement origin. These controls reserve ground
space; bridge clearance needs its own surface and volume design.

For grading or objects placed relative to a route, read the Plan's spline network and call
`splines.nearest(network, { x, z })`. Its result provides the chosen spline and a sample with
distance and interpolated height. Grade a platform with `fields.blend` over the shared Plan
polygon instead of rebuilding its outline in each consumer.

Add the Plan to the world's `plans` array. Give cross-region splines endpoints
on the full macro-region bounds so adjacent outputs meet at the same boundary.

## Add water

All water is Base water: the Engine shapes the terrain around it, then renders
and simulates it. Declare it in one of three ways.

A sea comes with `nature.temperateNature`. Set `terrain.coast` to place its
shoreline: the sea lies toward `seaward` and the preset terrain stays inland.
The waterline meanders up to 140 m either side of the line through `through`,
and changing `reliefMeters` keeps the coastline in place but moves the sea
surface with the relief.

```ts
base: bases.preset(nature.temperateNature, {
  overrides: {
    terrain: { coast: { through: { x: 0, z: 400 }, seaward: { x: 0, z: 1 } } },
  },
}),
```

Ask the attached World where the generated waterline is instead of scanning
heights or hard-coding the sea level. `water.nearestShore` answers from the
terrain before cells stream in:

```ts
const water = attachment.water;
const shore = water?.nearestShore(0, 400);
if (!water || !shore) throw new Error('No shoreline found near the spawn area.');
const inland = 30;
const x = shore.position.x - shore.seaward.x * inland;
const z = shore.position.z - shore.seaward.z * inland;
const y = attachment.sampleHeight(x, z);
if (y === undefined || water.sampleSurface(x, z)) {
  throw new Error('The shoreline spawn candidate is not dry terrain.');
}
const spawnCandidate = { x, y, z };
```

This finds a candidate, not a ready character spawn. Check the candidate's slope,
character clearance and route to the shore for the game's needs. Point streaming
interest at the candidate and keep the character inactive until
`attachment.readinessAt(x, z, y).physics` is true. Height and water queries work
before collision streams in. During scene activation, collision is prepared without
advancing gameplay; after activation, collision commits on physics ticks. Check local
physics readiness after `settle()` rather than assuming the candidate is ready. If startup
times out, report a loading failure instead of creating a character at a guessed
height. In Play, create or teleport the physics character through its controller.

To keep the player out of the sea, test the target column with
`attachment.water.sampleSurface(x, z)`: it returns a sample only over water, and
its `depth` says whether that water is deeper than the player may wade.

Rivers and lakes are Plan outputs. Present a spline output `as: 'river'`, whose
point `height` is the water surface in world metres and must not rise along the
spline, or a polygon output `as: 'lake'`, whose surface settles at the lowest
point of its shore. List them in `semantics.hydrology.outputs`, and give the world
`hydrology.prefetchRegions`: the level-0 macro regions, 512 m each, whose water
must exist before the first frame. Region `{ level: 0, x, z }` covers
`x * 512 .. (x + 1) * 512` and `z * 512 .. (z + 1) * 512`.

```ts
const water = definePcgPlan({
  id: 'game.water',
  version: 1,
  outputs: {
    river: { kind: 'splines', present: { as: 'river', width: 10, depth: 2 } },
    pond: { kind: 'polygons', present: { as: 'lake', depth: 4 } },
  },
  semantics: { hydrology: { outputs: ['river', 'pond'] } },
  params: {},
  plan: ({ region }) => ({
    river: splines.network(
      splines.create(`${region.id}/river`, [
        { x: region.bounds.minX, z: 200, height: 40 },
        { x: region.bounds.maxX, z: 200, height: 40 },
      ]),
    ),
    pond: [
      polygons.create(`${region.id}/pond`, [
        { x: region.bounds.minX + 100, z: region.bounds.minZ + 300 },
        { x: region.bounds.minX + 160, z: region.bounds.minZ + 300 },
        { x: region.bounds.minX + 160, z: region.bounds.minZ + 360 },
        { x: region.bounds.minX + 100, z: region.bounds.minZ + 360 },
      ]),
    ],
  }),
});

export const world = definePcgWorld({
  base: bases.preset(nature.temperateNature),
  seed: 'river-game',
  plans: [water],
  hydrology: { prefetchRegions: [{ level: 0, x: 0, z: 0 }] },
});
```

Outdoor PCG Worlds take their season, sky, fog, sun, and clouds from the World
Environment. When the user has not specified an initial time, start at noon:
`time: 'day'` selects `timeOfDay: 0.5`. Use clear weather and enough visibility to
read the landscape unless the brief specifies another atmosphere. A coastal,
forest, or cinematic setting alone does not request a morning start. Use another
initial time when the user requests it or an explicit gameplay requirement needs it.

```ts
worldEnvironment: {
  initial: { season: 'summer', time: 'day', preset: 'clear' },
},
```

Set this on `defineGame`; every PCG World follows it. Without `worldEnvironment`,
outdoor worlds show a fixed summer day with clear weather. Grass, bushes,
terrain, and roads take that atmosphere's radiance; tree meshes and impostors take
half. Caves and underwater reefs light themselves.

For a running day/night cycle, configure `dayLengthSeconds` in the initial
environment and call `set({ preset }, durationSeconds)` when weather is selected.
Do not drive the clock with per-frame `set({ timeOfDay }, 0)`, which replaces the
weather transition. See [world-environment.d.ts](../engine-api/world-environment.d.ts)
for patch and transition semantics.

## Authoring rules

- Preserve world, region, site, path, room, and instance IDs when changing rules.
- Increment a definition's version only when intentionally changing generated
  identity or compatibility.
- Use kit semantic roles for PCG assets; do not embed asset URLs or UUIDs in a
  recipe.
- Persist authored exceptions and gameplay state, not generated meshes or Three
  objects.
- Import public `pcg-*` entries only. Internal kernel, worker, presentation, and
  physics modules are Engine implementation details.

Compile after changing the declaration. PCG does not introduce a separate
runtime-testing requirement.
